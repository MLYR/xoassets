# 业务口径与数据规则

## 1. 用户隔离

- 所有用户业务表必须带 `user_id`。
- 所有查询、修改、删除必须通过当前登录用户隔离数据。
- 任何用户不得访问其他用户的数据。
- CSV 导出只允许导出当前登录用户自己的数据。
- 预算、资产目标、AI 报告、交易流水、账户、持仓均必须按当前 `user_id` 隔离。

## 2. 资产口径

```text
总资产 = 现金类账户余额 + 投资资产市值
总负债 = 信用卡负债 + 借款 + 贷款
净资产 = 总资产 - 总负债
今日净资产变化 = 今日净资产 - 昨日净资产
```

规则：

- 首页和统计总资产口径优先使用资产快照。
- 没有快照时页面可退回当前实时概览。
- 首页总资产与净资产优先取 `/api/snapshots/latest`；`/api/dashboard/overview` 作为首页补充概览，不作为最终总资产来源。
- `/api/snapshots/latest` 缺少较昨日或较月初基准快照时，后端必须返回 `null`。
- 前端展示 `--`，不能用 0 冒充缺失对比。
- 现金资产按账户初始余额 + 快照日前普通流水 / 投资交易 / 余额修正重建历史余额。
- 不能用当前 `xo_account.balance` 回填历史。
- 投资资产必须按快照日重建历史头寸。
- 不能用当前 `xo_holding` 数量回填历史。

## 3. 收支口径

- 新增支出：扣减账户余额。
- 新增收入：增加账户余额。
- 转账：不计入收入支出，只影响账户余额，不影响净资产。
- 退款：抵扣支出。
- 预算使用额从 `xo_transaction` 汇总。
- 转账不计入预算使用额。

## 4. 投资口径

```text
投资浮动盈亏 = 当前市值 - 持仓成本
投资收益率 = 浮动盈亏 / 持仓成本 * 100%
```

规则：

- 投资买入 / 卖出必须选择当前用户资金账户。
- 买入扣减账户余额。
- 卖出增加账户余额。
- 投资交易、账户、持仓更新必须在同一事务内完成。
- 投资交易不写入普通流水。
- 投资交易补录、基金确认或撤销后必须从交易日起重建投资日快照和资产快照。
- 前端展示市值、成本和盈亏必须使用后端返回字段。
- 前端不得用格式化后的当前价反算市值、成本或盈亏。
- 投资收益以后端计算为准，前端只展示。

## 5. 投资收益展示口径

基金、股票、虚拟货币收益口径必须分开：

```text
基金：昨日收益
股票：今日收益
虚拟货币：24h 收益
总投资：分项展示，不强行合并为今日收益
```

规则：

- 基金不要展示为“今日收益”。
- 所有资产只有当前价格日期等于今天时才计算今日收益。
- 基金和股票还必须当天为交易日。
- 休市日返回 `todayPriceAvailable=false`。
- 休市日返回 `priceStatus=MARKET_CLOSED`。
- 交易日未更新返回 `priceStatus=TODAY_PRICE_NOT_AVAILABLE`。
- 收益基准价格或基准数量缺失时，对应字段返回 `null`。
- 前端展示 `暂无 / --`。
- 全持仓收益日历由后端返回整月日期；只有当前统计资产全部休市时才返回 `marketClosed=true` / `statusLabel=休市`，前端不得自行猜测休市。
- 不能用历史价、兜底价或其他值冒充今日价。

## 6. 基金交易口径

- 基金买入默认支持 `AMOUNT_NAV` 金额净值录入。
- 基金可先创建 0 份额持仓。
- `transaction_time` 表示用户实际买入时间。
- 后端通过 `xo_market_calendar` 计算有效申请日和确认日。
- 15:00:00 及以前按当天申请。
- 15:00 后或非交易日顺延。
- 普通基金 T+1。
- 名称包含 `QDII` 的基金 T+2。
- 确认日净值缺失时交易保持 `PENDING_CONFIRM`。
- 股票等资产继续使用 `QUANTITY_PRICE` 数量价格录入。
- 基金金额买入从实际申购日至确认日前按在途投资资产计入。
- 补跑确认日前历史快照时必须保留这段在途金额，避免已扣款但未确认份额导致净资产假跌。
- 投资总览需单独返回在途基金金额，投资资产总额 = 已确认持仓市值 + 在途基金金额。

## 7. 持仓规则

- 持仓创建后不允许删除。
- 清仓持仓状态显示“清仓”。
- 列表持有收益展示已实现收益 + 当前浮动盈亏。
- 持仓详情总市值走势使用后端 `chartPoints`。
- 不得用当前 0 份额倒推历史。
- 历史持仓补录必须通过投资买入 / 卖出交易表达。
- 不允许直接修改当前持仓数量倒推历史。
- 手工初始化持仓有后续买卖时，先注入反推手工底仓再应用交易流水。
- 卖出净变化不能提前截断为 0，避免清仓后历史份额丢失。

## 8. 数值精度

- 投资数量统一保留 10 位小数。
- 手续费、成本、市值、盈亏和收益率统一按 4 位小数计算。
- 当前价和日级价保留 8 位。
- CRYPTO 当前价至少展示 6 位。
- FUND / STOCK 展示 4 位。
- 后端返回给前端的 Long ID 必须按字符串处理。
- 前端不得用 `number` 保存业务 ID，避免 JavaScript 精度丢失。
- 移动端金额展示必须统一格式化，最终计算以后端为准。

## 9. 事务规则

### 普通流水

- 新增支出：保存流水、扣减账户余额、刷新当日汇总必须在同一事务中完成。
- 新增收入：保存流水、增加账户余额、刷新当日汇总必须在同一事务中完成。
- 删除流水：必须处理账户余额反向恢复和每日汇总刷新。
- 修改流水：必须处理原流水反向恢复、新流水影响和每日汇总刷新。

### 转账

- 转账保存流水、转出扣款、转入加款、刷新汇总必须一致提交。
- 转账不计入收入支出。
- 转账账户不能相同。

### 投资交易

- 投资买入：保存买入交易、扣减现金账户、增加或更新持仓、重算平均成本、刷新汇总。
- 投资卖出：校验持仓数量、保存卖出交易、减少持仓、增加现金账户、计算已实现盈亏、刷新汇总。
- 投资卖出数量超过持仓时必须提示持仓不足。
- 投资交易撤销必须使用 `cost_amount` 反向恢复历史成本。
- 投资交易撤销不物理删除交易。
- 已撤销交易保留展示，但不参与账户资金明细汇总。

## 10. 行情与快照

### 行情来源

- CRYPTO 使用 CoinGecko。
- FUND 使用天天基金 F10 历史净值表和实时净值兜底。
- A 股使用新浪行情。
- 美股使用 Yahoo Finance。
- 第三方行情只能由后端调用。
- 前端和移动端不直接调用第三方行情源。

### 行情缓存 TTL

- CRYPTO：15 分钟。
- STOCK：15 分钟。
- FUND：1 天。
- MANUAL：不过期。

### Redis 原始快照

- 股票和虚拟货币原始快照写入 Redis ZSET。
- Key 格式：`price:snapshot:{assetId}:{yyyyMM}`。
- TTL：3 天。
- 读取某天原始快照必须通过当天起止毫秒 score 范围查询。
- 禁止全量拉取整月 ZSET 后内存筛选。

### 长期表

- `xo_asset_price_daily` 保存长期日级价格。
- `xo_investment_holding_daily_profit` 保存每个持仓展示日真实收益。
- `xo_investment_daily_snapshot` 保存用户投资日快照。
- `xo_asset_snapshot` 保存资产快照。

## 11. 市场日历

- `xo_market_calendar` 是交易日判断的数据库权威来源。
- 年度补齐任务只生成基础周末日历。
- 交易所特殊休市日通过迁移脚本或人工修正写入数据库。
- 禁止把年度休市日写死在 Java 或 yml。
- 股票只在开盘日 09:30-15:00 之间拉取第三方行情。
- 虚拟货币全天每 15 分钟刷新。
- 刷新失败保留最近价格。
- 定时刷新失败不能影响应用启动。

## 12. AI 报告

- AI 报告当前为模板化财务复盘。
- AI 报告基于真实统计数据生成。
- AI 报告保存到 `xo_ai_report`。
- 当前不调用真实 AI。
- 不提供投资买卖建议。
- AI 请求前尽量脱敏个人财务数据。
- AI 报告生成失败时标记失败，并支持手动重试。
